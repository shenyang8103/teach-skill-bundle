# Visualize

一张图只有在能展示文字展示不了的东西时才值得——形状、结构、方向、关系、几何。本技能产出**一张**这样的图，保证它**正确**（你渲染后亲眼核对再交付），并内联进教学。

你是**创意总监**。你决定确切的想法，并把它提炼到最少承载元素。WorkBuddy 的 **Visualizer（read_me + show_widget）** 负责实际的绘制、渲染、视觉核对与展示——你只需 brief 它并内联它返回的内容。

## 何时可视化（何时不）

教学系统在他脑中建一张**依赖图**——公理在根，派生事实挂在上面。一张图恰好在让那结构（或几何）可见时有力量。在以下情况出手：

- 想法是**结构或关系**：依赖、带部件与箭头的系统、流程/管线、一组交换的时序、状态机、树/层级、对比、包含关系（里 vs 外）。
- 想法是**空间或几何**：坐标几何、数轴、向量、函数形状、物理排布。

当散文或单个方程已经承载了它，就**不要**可视化。一张只是重述旁边句子的装饰图，增加噪声也增加出错机会。拿不准就别——缺一张图比一张错的图便宜。

## 选类型

- **关系/结构型**（依赖图、流程图、时序/状态/ER/类图、树、时间线）→ 用 **mermaid**（在 show_widget 的 HTML 里加载 mermaid 渲染，或输出 ```mermaid``` 代码块）。
- **空间/几何型**（精确坐标、几何图形、数轴、向量、函数图像、自定义形状）→ 用 **SVG**（show_widget 直接写 SVG）。

经验法则：节点-边/关系 → mermaid；位置-形状/几何 → SVG。

**mermaid 标签安全规则（强制）：** 节点标签内**禁用半角括号 `(` `)`、方括号 `[` `]`、花括号 `{` `}`、双引号 `"`**——它们是 mermaid 的节点形状控制符；WorkBuddy 内置渲染器不保证按"带引号字符串"解析标签，实测半角括号会触发 `Parse error ... got 'PS'`（`PS` 即 `(` 记号），即便已用双引号包住。需要括号语义用**全角（）**或冒号/破折号改写；引号可加，但内容必须**去掉引号也能解析**。`→`、`≥`、`/`、`<br/>` 等实测安全。出图前自查一遍标签。

## 给好自己的 brief：一个想法，最少元素

最常见的失败是**塞太满**——每个多余标签既让图更难读，也更难排对。brief 前先剪到承载想法的最少元素，对每个元素问：*删掉它，想法还清楚吗？* 是就删。

给 maker 概念**和**具体元素——不是模糊主题，也不是长清单。

- 差："画个图说明 TCP 怎么工作"
- 好："graph TD：顶部一个 'packet' 节点；箭头向下到 'ordering' 和 'retransmit on loss'；两条箭头再向下汇入 'reliable stream'。无标题。体现可靠性是*从*包构建出来的，而非并列。"

保持想法完整，但信任 maker 来构图；若你的 brief 列了超过约 5–7 个元素，先砍。

## 产出（render-and-inspect 循环）

1. **规划坐标/结构。** 选 viewBox（SVG）或图类型（mermaid），先想好每个元素放哪。留边距，别让任何东西贴边。保持一个想法、少元素。
2. **绘制并渲染。** 先调用 `read_me`（模块 diagram/interactive/chart/art 按需）加载样式，再用 `show_widget` 写出 SVG/HTML 并渲染：
   - **mermaid**：在 HTML widget 中用 `<script type="module">` 从 `https://cdn.jsdelivr.net/npm/mermaid/dist/mermaid.esm.min.mjs` 加载 mermaid，再 `mermaid.render()` 给定定义。
   - **SVG**：直接写完整 `<svg>`，白/透明背景，可读 `font-family="sans-serif"`，字号足够大（内联展示时能读）。
3. **亲眼核对（最关键的一步）。** 看渲染结果：
   - 每个坐标/角度/方向/比例真的对吗？拿不准就重推几何。
   - 标签清晰、不压线、不互相重叠吗？
   - 有被 viewBox 裁切、太小或太挤的吗？
   - 学习者仅看这张图就能秒懂意图吗？
4. **迭代** 直到正确、干净。用 Edit 改进源再重渲染。只画 brief 指定的内容，不杜撰数据点、数值或形状来填空。
5. **交付**：把渲染好的图内联到你的教学回复里，用一句话引入，让它承载想法——不必在散文里再把每个元素复述一遍。

## 为什么可靠

- 你**亲眼看过**才交付，所以"渲染正常但内容有错"会在到达用户前被抓到。
- 内联渲染意味着"你核对过的"与"用户看到的"像素一致——无重渲染漂移。

> 若一张图作者工作量大，可派一个 **Agent 子代理**（general-purpose）充当 maker，把上述 brief 与 render-and-inspect 循环交给它，最后把返回的文件/内容内联展示。子代理同样要先 `read_me` 再 `show_widget`，并真正"看"渲染结果。
